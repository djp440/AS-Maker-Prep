# 模块开发指南: Services - Market Data Service

## 1. 核心职责
- 为策略模块提供统一、实时的市场数据接口。
- 整合来自 WebSocket 的实时数据和来自 REST API 的历史数据。
- 计算并缓存策略所需衍生数据，如市场中间价和波动率。

## 2. 技术实现要点
- **结构**: 创建 `MarketDataService` 类，为每个交易对维护一个独立的数据状态。
- **数据源**: 
  - **实时数据**: 监听 `WebSocketManager` 分发的事件（如 `ticker`, `orderbook`）。
  - **历史数据**: 通过 `ExchangeService` 的 `fetchOHLCV` 方法获取 K 线数据。
- **缓存**: 在内存中缓存最新的市场数据，如中间价、买一卖一价、波动率等，供策略模块快速访问。

## 3. 核心数据与计算

### 3.1. 市场中间价 (s)
- **计算方式**: `(best_bid + best_ask) / 2`。
- **数据来源**: 从 `watchTicker` 或 `watchOrderBook` 的实时数据中获取最高买价（best_bid）和最低卖价（best_ask）。
- **更新频率**: 实时更新。
- **接口**: `getMidPrice(symbol)`。

### 3.2. 市场波动率 (σ)
- **计算逻辑**: 
  1. 定期（例如，每分钟或每15分钟）通过 `ExchangeService.fetchOHLCV` 获取最新的 K 线数据。
  2. 使用 `VOLATILITY_LOOKBACK` 周期（例如，最近14根K线）的收盘价计算对数收益率。
  3. 计算这些收益率的标准差，作为市场波动率 `σ`。
- **缓存**: 计算出的波动率应被缓存，直到下一个计算周期。
- **接口**: `getVolatility(symbol)`。

### 3.3. 数据验证
- **中间价验证**: 检查买卖价差是否异常扩大。如果价差超过某个阈值（例如，市场平均价差的5倍），则认为当前中间价不可靠，可以暂时挂起报价或使用最近的成交价作为参考。
- **波动率验证**: 检查计算出的波动率是否在合理范围内。如果波动率突然飙升（例如，超过日均波动率的3倍），应触发风险警报，并可能暂停交易。

## 4. 与其他模块的交互
- **依赖**: `WebSocketManager`, `ExchangeService`, `Config`, `Logger`。
- **被依赖**:
  - `strategy`: 核心依赖方。调用 `getMidPrice(symbol)` 和 `getVolatility(symbol)` 获取计算所需的核心参数。
- **交互模式**: `Strategy` 模块在每次计算循环时，都会从 `MarketDataService` 的实例中获取最新的数据。

## 5. 注意事项
- **数据同步**: 必须确保用于计算的数据是同步的。例如，在收到新的 Ticker 数据更新中间价后，应立即触发一次策略的重新计算。
- **多交易对隔离**: 每个交易对的市场数据（中间价、波动率等）必须严格隔离，不能相互影响。
- **启动初始化**: 在程序启动时，需要主动获取一次历史 K 线来初始化波动率，而不是等待第一个周期结束。
