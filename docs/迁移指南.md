从AS模型迁移到GLFT模型的开发文档更新指南
引言：为何迁移？
在文档的引言部分，首先需要阐明迁移的动机。AS模型是一个开创性的框架，但其核心是围绕一个有限的交易周期（由终端时间 T 定义）建立的 。这使得它非常适合有明确开盘和收盘时间的传统股票市场。然而，对于外汇或加密货币等24/7不间断交易的市场，这个“会话式”的假设就不再适用 。   

迁移到GLFT模型的**渐近解（asymptotic solution）**将带来以下核心优势，应在文档中予以强调：

消除时间依赖性：GLFT的渐近解不依赖于终端时间 T，使其天然适用于连续运行的交易策略 。   

简化计算：渐近公式将复杂的报价问题分解为更直观的“半价差”（half-spread）和“库存偏度”（inventory skew），计算上更为高效 。   

更严格的风险管理：GLFT模型明确地引入了硬性的库存限制（|q| ≤ Q），这提供了一个比AS模型更真实的风险控制机制 。   

第一部分：核心逻辑变更——从“保留价格”到“半价差与偏度”
这是文档中最重要的部分，需要详细描述报价计算逻辑的根本性转变。

1.1 废弃的概念：保留价格 (Reservation Price)

旧AS逻辑：您的现有文档应描述了基于以下公式计算保留价格 r(s, q, t)：
r(s, q, t) = s - qγσ²(T-t)
其中 s 是中价，q 是库存，γ 是风险厌恶系数，σ 是波动率，(T-t) 是剩余时间 。   

迁移操作：在您的新文档中，明确指出保留价格和终端时间 T 这两个概念将被废弃。所有依赖于 (T-t) 的计算逻辑都需要被移除。

1.2 引入新概念：半价差 (Half-Spread) 与库存偏度 (Inventory Skew)

新GLFT逻辑：GLFT模型的渐近解将最优报价的计算分解为两个独立的部分。您需要更新文档以反映这一点。最优的买卖报价深度（δ_b, δ_a）现在由以下方式确定 ：   

bid_depth(q) = half_spread + skew × q

ask_depth(q) = half_spread - skew × q

最终的报价为：

bid_price = mid_price - bid_depth(q)

ask_price = mid_price + ask_depth(q)

新公式：文档需要包含计算 half_spread 和 skew 的新公式。这些公式仅依赖于那些在AS模型中也存在的参数（γ, σ, A, k），但组合方式不同 ：   

half_spread = C₁ + C₂σ²

skew = C₂σ
其中 C₁ 和 C₂ 是由风险厌恶系数 γ 和订单流强度参数 A、k 决定的常数 。您的开发团队需要实现计算这些常数的函数。   

第二部分：参数校准模块的更新
您的参数校准文档大部分可以保留，但需要做一些关键的调整。

保留的参数：

波动率 (σ)：计算方法不变，仍然从历史中价的对数收益率中估计。

风险厌恶系数 (γ)：这仍然是一个由策略师主观设定的参数，代表风险偏好。

订单到达强度 (A, k)：校准方法不变。继续使用对数线性回归将经验订单到达率拟合到指数函数 λ(δ) = A * exp(-kδ) 上 。   

移除的参数：

终端时间 (T)：由于GLFT渐近模型是为连续交易设计的，因此不再需要此参数。应从所有配置文件和计算逻辑中移除。

新增的参数：

最大库存 (Q)：GLFT模型引入了硬性的最大库存限制。您需要在文档中增加这一参数，它定义了策略允许持有的最大（多头）或最小（空头）头寸。当 q 达到 Q 时，策略应停止下买单；当 q 达到 -Q 时，应停止下卖单 。   

第三部分：程序实现与伪代码更新

AS模型伪代码（示例）

// 旧逻辑
function get_as_quotes(mid_price, inventory, time_to_expiry):
  // 1. 计算保留价格
  reservation_price = mid_price - inventory * gamma * vol^2 * time_to_expiry

  // 2. 计算最优总价差
  total_spread = gamma * vol^2 * time_to_expiry + (2/gamma) * log(1 + gamma/k)

  // 3. 设置报价
  bid_price = reservation_price - total_spread / 2
  ask_price = reservation_price + total_spread / 2
  return bid_price, ask_price
GLFT模型伪代码（迁移后）

// 新逻辑
function get_glft_quotes(mid_price, inventory):
  // 1. 计算半价差和偏度 (C1, C2为预先根据A, k, gamma计算的常数)
  half_spread = C1 + C2 * vol^2
  skew = C2 * vol

  // 2. 计算买卖报价深度
  bid_depth = half_spread + skew * inventory
  ask_depth = half_spread - skew * inventory

  // 3. 设置报价
  bid_price = mid_price - bid_depth
  ask_price = mid_price + ask_depth

  // 4. 应用库存限制
  if inventory >= max_inventory_Q:
    bid_price = null // 停止下买单
  if inventory <= -max_inventory_Q:
    ask_price = null // 停止下卖单

  return bid_price, ask_price
第四部分：回测与评估标准
在文档的测试部分，您应指出，虽然目标函数（最大化期望财富效用）保持不变，但评估策略成功的标准应更侧重于风险调整后收益。

预期结果：与AS模型相比，GLFT策略的夏普比率（Sharpe Ratio）和索提诺比率（Sortino Ratio）预计会更高，而最大回撤（Max Drawdown）和期末库存绝对值则会更低。这证明了GLFT在库存风险控制方面的优越性。

通过遵循这份指南更新您的开发文档，您的团队将能清晰地理解从AS到GLFT的逻辑演变，并顺利地将您的做市程序迁移到一个更强大、更灵活的现代框架上。
