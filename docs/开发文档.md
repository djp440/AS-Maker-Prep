# Avellaneda做市策略开发文档

## 项目概述
基于Avellaneda-Stoikov模型（准备迁移至GLFT）的自动合约做市程序，使用Node.js + CCXT在Bitget交易所执行多交易对做市策略。

## 技术栈
- **运行环境**: Node.js 18+
- **交易框架**: CCXT
- **配置管理**: dotenv
- **日志系统**: Winston
- **时间处理**: Day.js

## Bitget交易所接口

### 连接方式
- **数据获取**: WebSocket (账户、订单、行情)
- **订单操作**: REST API (下单、撤单)

### WebSocket限制
- **连接**: 5分钟内最多300次连接，单IP最多100并发
- **订阅**: 每小时最多240次订阅，单连接建议≤50频道
- **心跳**: 30秒发送ping，2分钟无响应断开
- **重连**: 24小时强制断开，需自动重连
- **速率**: 每秒最多10消息

### 连接稳定性机制
- **重连策略**: 指数退避(1s-60s)，清理订阅状态，限制重连次数
- **状态恢复**: 重连后同步账户状态，对比订单变化，重新订阅频道
- **连接监控**: 监控连接状态、数据流、延迟指标

### API速率控制
- **频率控制**: 令牌桶算法，优先级队列(紧急订单>查询>历史)
- **并发控制**: 限制并发数，关键操作串行化
- **错误处理**: 识别限制错误码，智能重试，IP封禁保护

### 模拟盘配置
要启用模拟盘功能，请在 `.env` 文件中进行相应配置。您需要使用模拟盘专用的API Key，并根据CCXT的规范在请求中添加额外参数。

**模拟盘REST API**
- **启用方式**: 在CCXT实例化时，通过 `options` 对象设置 `papertrading: true` 或类似的参数，具体取决于CCXT对Bitget模拟盘的支持方式。通常，这会通过在请求头中添加 `paptrading: 1` 来实现。
- **API Key**: 请使用您在Bitget模拟盘申请的API Key、Secret和Passphrase。

**模拟盘WebSocket**
- **连接地址**:
  - **公共频道**: `wss://wspap.bitget.com/v2/ws/public`
  - **私有频道**: `wss://wspap.bitget.com/v2/ws/private`
- **认证**: 使用模拟盘的API Key进行认证。

在代码实现中，需要根据配置动态切换实盘与模拟盘的API端点和WebSocket地址。

### WebSocket认证
**认证字段**: api_key, passphrase, timestamp, sign

**签名算法(HMAC-SHA256)**:
```
Message = timestamp + "GET" + "/user/verify"
Signature = hmac_sha256(API_SECRET, Message)
sign = base64.encode(Signature)
```

### 参数说明
#### 基础参数
- **SYMBOL**: 交易对(CCXT格式)
- **RISK_AVERSION**(γ): 风险厌恶系数，影响库存对报价的调整幅度
- **ORDER_FLOW_A**: 订单流强度参数A，用于计算λ(δ) = A * exp(-kδ)
- **ORDER_FLOW_K**: 订单流强度参数k，用于计算λ(δ) = A * exp(-kδ)
- **MAX_INVENTORY_Q**: 最大库存限制Q，当|q| ≥ Q时停止相应方向下单
- **ORDER_AMOUNT**: 单次下单占总权益百分比(如0.01表示1%)
- **VOLATILITY_LOOKBACK**: 波动率计算回看周期(K线数)
- **KLINE_INTERVAL**: K线周期
- **LEVERAGE**: 杠杆倍数
- **TRADE_SIDE**: 交易方向(long/short/both)

#### 中低频改造新增参数
- **MIN_SPREAD_PCT**: 最小价差百分比(如0.06表示0.06%)，作为盈利基础
- **HALF_SPREAD_PCT**: 半价差百分比(如0.04表示0.04%)，实际使用的基础价差
- **REBALANCE_TIME_INTERVAL**: 重新平衡时间间隔(秒)，控制订单更新频率
- **PRICE_MOVE_THRESHOLD_PCT**: 价格变动触发阈值(如0.05表示0.05%)，超过此幅度才更新订单
- **USE_TRADITIONAL_GLFT**: 是否使用传统GLFT公式(true/false)，false时使用固定价差+偏度模式

## 核心算法：GLFT模型（中低频改造版）

### 核心思想转变：从"抢时间"到"管库存"
**高频玩家目标**: 利用速度优势，在极小价差里快进快出，靠巨大成交量和手续费返佣盈利
**我们的目标**: 因网络和手续费限制，设置足够宽的价差（如0.06%）保证单笔利润，优势不再是速度，而是更长持单时间和更聪明的库存管理

### GLFT模型的核心价值
对我们最大的价值不再是计算出的微小"理论价差"，而是优雅的**库存风险管理机制——偏度（Skew）**

### 核心优势
- **消除时间依赖性**: 不依赖终端时间T，天然适用于24/7连续交易
- **简化计算**: 将复杂报价问题分解为半价差和库存偏度
- **严格风险管理**: 引入硬性库存限制|q| ≤ Q
- **适应中低频**: 通过宽价差和智能库存管理替代高频优势

### 中低频改造的报价策略

#### 1. 接受并使用宽价差
- **最小价差基准**: `min_spread = 0.06%` 作为盈利基础
- **半价差设定**: `half_spread = 0.04%`（总价差0.08%），增加安全边际
- **不再追求理论最优**: 放弃微小的理论价差，确保单笔交易有足够利润覆盖手续费和网络延迟风险

#### 2. 偏度（Skew）发挥核心作用
**库存自动调节机制**:
- **有货时** (库存 q > 0): 内心更想卖，买单放得更远，卖单更贴近中价
  - `bid_price = mid_price - (half_spread + skew * q)`
  - `ask_price = mid_price + (half_spread - skew * q)`
- **空仓时** (库存 q < 0): 内心更想买，卖单挂得更远，买单更贴近中价

#### 3. 降低交易频率
**触发条件设定**:
- **时间触发**: 每隔5-10秒重新评估价格和库存，更新订单
- **价格变动触发**: 中价移动超过0.05%时才撤销旧单，挂上新单
- **避免过度反应**: 不对市场每次微小跳动做出反应，减少网络延迟影响

#### 4. 传统GLFT公式（作为参考）
**核心公式**:
- `half_spread = C₁ + C₂ * σ²`
- `skew = C₂ * σ`

**常数计算**:
- `C₁ = f(γ, A, k)` - 由风险厌恶系数和订单流强度决定
- `C₂ = g(γ, A, k)` - 由风险厌恶系数和订单流强度决定

### 标准化库存量计算
**公式**: `q = (持仓价值 / 总资产) / MAX_INVENTORY_Q`

**计算步骤**:
1. 持仓价值 = |持仓数量| × 当前市价
2. 库存比例 = 持仓价值 / 总资产
3. 标准化库存量 = 库存比例 / MAX_INVENTORY_Q
4. 符号: 多头为正，空头为负

**示例**: 
- 总资产100,000 USDT，BTC持仓0.5个，价格50,000
- 持仓价值 = 0.5 × 50,000 = 25,000 USDT
- 库存比例 = 25,000 / 100,000 = 0.25
- 若MAX_INVENTORY_Q=0.2，则q = +0.25/0.2 = +1.25

### 报价深度计算
**公式**:
- `bid_depth = half_spread + skew × q`
- `ask_depth = half_spread - skew × q`

### 最终报价
- **买价**: `bid_price = mid_price - bid_depth`
- **卖价**: `ask_price = mid_price + ask_depth`

**库存限制机制**:
- 当 `q ≥ Q` 时，停止下买单（bid_price = null）
- 当 `q ≤ -Q` 时，停止下卖单（ask_price = null）

对于交易方向为long的场景，应该在买价处开多仓，在卖价处平多仓
对于交易方向为short的场景，应该在卖价处开空仓，在买价处平空仓
对于交易方向为both场景，应该在买价处开多仓、平空仓，在卖价处开空仓、平多仓

### 风险控制机制

**异常检测**:
- 波动率上限阈值(如3倍日均)，超过暂停报价
- 价差保护，最大不超过市场价差2倍
- 中间价验证，异常时使用成交价/VWAP

**库存管理**:
- 通过半价差和库存偏度公式自动调节报价
- 当库存过多(q>0)时，skew×q增大bid_depth，降低买价吸引卖单
- 当库存不足(q<0)时，skew×q减小ask_depth，降低卖价吸引买单
- **硬性库存限制**: 当|q| ≥ Q时强制停止相应方向的下单
- 算法具备自平衡机制，结合硬性限制提供双重保护

## 合约交易执行逻辑

### 交易信号
- **开多**: 无仓/空仓时买入信号
- **平多**: 多仓时卖出信号  
- **开空**: 无仓/多仓时卖出信号
- **平空**: 空仓时买入信号

### 交易所精度处理

**价格精度调整**:
```javascript
// 根据交易所规则调整价格精度
function adjustPrice(price, tickSize) {
    return Math.round(price / tickSize) * tickSize;
}
```

**数量精度调整**:
```javascript
// 根据交易所规则调整数量精度
function adjustQuantity(quantity, stepSize, minQty) {
    const adjusted = Math.floor(quantity / stepSize) * stepSize;
    return Math.max(adjusted, minQty);
}
```

**关键精度参数**:
- `tickSize`: 价格最小变动单位(如0.1, 0.01)
- `stepSize`: 数量最小变动单位(如0.001)
- `minQty`: 最小下单数量
- `minNotional`: 最小下单金额(价格×数量)

**实际报价示例**:
```javascript
// 理论计算结果
const theoreticalBid = 49999.97998;
const theoreticalAsk = 49999.98002;

// 精度调整后
const actualBid = adjustPrice(theoreticalBid, 0.1); // 49999.9
const actualAsk = adjustPrice(theoreticalAsk, 0.1); // 50000.0
```

### 库存风险控制
- 下单前检查: 持仓+活动订单+新订单 ≤ MAX_INVENTORY

- 交易所错误: 按错误码分类处理
