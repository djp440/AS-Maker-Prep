# Windows控制台中文乱码问题解决方案

## 问题描述

在Windows系统中运行Node.js应用时，控制台输出的中文字符可能显示为乱码，例如：

```
[07:20:18.495] INFO: 鍒濆鍖栦氦鏄撴墍: bitget, 妯″紡: 妯℃嫙鐩?
[07:20:19.903] INFO: 浜ゆ槗鎵€杩炴帴鎴愬姛
```

## 问题原因

Windows控制台默认使用GBK编码（代码页936），而Node.js应用通常使用UTF-8编码输出中文字符，导致编码不匹配。

## 解决方案

### 方案1：使用项目提供的修复脚本（推荐）

```bash
# 运行编码修复脚本
npm run fix:encoding

# 或者直接运行
node scripts/fix_encoding.js
```

### 方案2：手动设置控制台编码

在PowerShell中执行：

```powershell
# 设置控制台代码页为UTF-8
chcp 65001
```

### 方案3：在代码中自动修复（已集成）

项目已在以下文件中集成了自动编码修复：

- `src/shared/logger.js` - 日志输出编码修复
- `test_connection.js` - 测试脚本编码修复

## 技术实现

### 1. 控制台代码页设置

```javascript
const { execSync } = require('child_process');
execSync('chcp 65001', { stdio: 'ignore' });
```

### 2. Node.js输出流编码设置

```javascript
process.stdout.setEncoding('utf8');
process.stderr.setEncoding('utf8');
```

### 3. Pino日志器配置

```javascript
stream: require('pino-pretty')({
  colorize: true,
  translateTime: 'HH:MM:ss.l',
  ignore: 'pid,hostname',
  messageFormat: '{msg}',
  destination: process.stdout,
  sync: true
})
```

## 常见问题

### Q: 修复后仍然显示乱码怎么办？

A: 尝试以下步骤：
1. 以管理员权限运行PowerShell
2. 手动执行 `chcp 65001`
3. 重新启动终端
4. 确保使用的是PowerShell而不是CMD

### Q: 为什么有些终端工具仍然显示乱码？

A: 某些第三方终端工具可能有自己的编码设置，需要在工具设置中将编码改为UTF-8。

### Q: 这个修复会影响其他应用吗？

A: 不会。编码设置只影响当前终端会话，不会永久改变系统设置。

## 最佳实践

1. **开发环境**：在项目启动脚本中自动设置编码
2. **生产环境**：确保服务器控制台支持UTF-8编码
3. **团队协作**：在项目文档中说明编码要求
4. **CI/CD**：在构建脚本中包含编码设置
